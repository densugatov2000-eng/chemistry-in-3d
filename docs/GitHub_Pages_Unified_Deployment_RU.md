# «Химия в 3D» v1.1. Публикация единого репозитория

Каталог расположен в корне репозитория `chemistry-in-3d`, а тренажёры — в `simulator/<slug>/`. GitHub Actions собирает каталог из паспортов, проверяет его и публикует папку `dist/`.

- [Каталог «Химия в 3D»](https://densugatov2000-eng.github.io/chemistry-in-3d/)
- [Прямая ссылка на тренажёр «Строение атома»](https://densugatov2000-eng.github.io/chemistry-in-3d/simulator/atomic-structure/)
- [Прежняя ссылка на тренажёр](https://densugatov2000-eng.github.io/atomic-structure-model/)

Первые две ссылки начнут работать после успешной публикации нового комплекта.

## 1. Распакуйте и проверьте проект локально

В примере ZIP находится в папке загрузок Windows. Для работы нужны Git и Python 3.12. После распаковки в рабочей папке непосредственно видны `index.html`, `simulator`, `scripts` и `.github`.

```powershell
# Распаковываем комплект в новую рабочую папку.
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\Chemistry_in_3D_v1_1_Unified_Repository.zip" -DestinationPath "$env:USERPROFILE\chemistry-in-3d"

# Переходим в корень проекта.
Set-Location "$env:USERPROFILE\chemistry-in-3d"

# Проверяем наличие Git и Python.
git --version
py --version

# Запускаем тесты паспортов, сборки и путей.
py -m unittest discover -s tests -v

# Собираем сайт и формируем dist/trainers.json.
py scripts/build_catalog.py

# Запускаем локальный сервер из папки готового сайта.
py -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Откройте [http://localhost:8000/](http://localhost:8000/) и [локальную страницу тренажёра](http://localhost:8000/simulator/atomic-structure/). Проверьте карточку, превью, поиск по слову «изотопы», фильтры, переход в тренажёр и ссылку «← Все тренажёры». Остановите сервер сочетанием **Ctrl+C**. На Linux используйте `python3` вместо `py`.

## 2. Создайте или обновите репозиторий GitHub

Если репозитория `chemistry-in-3d` ещё нет, создайте его в аккаунте `densugatov2000-eng` как публичный, без автоматического README и других стартовых файлов. Затем в распакованной папке выполните команды.

```powershell
# Инициализируем локальный репозиторий с основной веткой main.
git init -b main

# Добавляем исходники и проверяем список файлов перед коммитом.
git add --all
git status --short

# Сохраняем комплект в истории Git.
git commit -m "Publish unified Chemistry in 3D v1.1"

# Связываем локальный проект с репозиторием GitHub.
git remote add origin https://github.com/densugatov2000-eng/chemistry-in-3d.git

# Отправляем ветку main на GitHub.
git push -u origin main
```

Если репозиторий уже создан и содержит v1.0, клонируйте его в отдельную рабочую папку, перенесите поверх него файлы из нового архива и сохраните существующую историю Git. В рабочей копии уберите корневой `trainers.json` и прежний `assets/trainers/01-atomic-structure.webp`, если они там есть. Генератор создаёт реестр в `dist/`, а превью теперь лежит рядом с тренажёром. Перед коммитом проверьте, что прежние авторские файлы не потерялись.

```powershell
# Клонируем существующий репозиторий в отдельную папку.
git clone https://github.com/densugatov2000-eng/chemistry-in-3d.git chemistry-in-3d-existing

# Переходим в рабочую копию перед переносом распакованного комплекта.
Set-Location .\chemistry-in-3d-existing

# После переноса комплекта запускаем локальные проверки.
py -m unittest discover -s tests -v
py scripts/build_catalog.py

# Проверяем изменения, сохраняем и отправляем их.
git add --all
git status --short
git commit -m "Migrate catalog and trainer into a single Pages repository"
git push origin main
```

## 3. Включите публикацию через GitHub Actions

1. На GitHub откройте **Settings → Pages**. В блоке **Build and deployment → Source** выберите **GitHub Actions**.
2. На вкладке **Actions** откройте процесс **Deploy Chemistry in 3D to Pages**. Если первый запуск произошёл до переключения источника, нажмите **Run workflow** и выберите `main`.
3. Дождитесь зелёных результатов задач **build** и **deploy**. Первая запускает тесты и передаёт GitHub только содержимое `dist/`. Вторая выполняет публикацию в окружении `github-pages`. При желании ограничьте это окружение веткой `main` в **Settings → Environments → github-pages**.
4. Откройте опубликованные адреса по ссылкам в начале документа. Проверьте переходы в обе стороны, прямой вход в тренажёр, кнопку «Назад» и открытие с телефона.
5. В том же браузере и профиле, где ранее проходили практику по старому адресу GitHub Pages, проверьте восстановление прогресса. Старый и новый пути используют тот же HTTPS-источник и ключ `atomic-structure-trainer-v3`. Локальный сервер использует собственное хранилище.

[Документация GitHub по публикации Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 4. Добавляйте и обновляйте тренажёры

Создайте или получите готовую папку тренажёра по стандарту [Trainer_Standard_RU.md](Trainer_Standard_RU.md). Поместите её в `simulator/`. В `manifest.json` задайте постоянный уникальный `id`, уникальный номер и готовые данные карточки. Для публикации укажите `published`.

```powershell
# Проверяем паспорта и наличие ресурсов.
py -m unittest discover -s tests -v
py scripts/build_catalog.py

# Добавляем папку нового тренажёра. Замените new-trainer именем своей папки.
git add -- simulator/new-trainer

# Публикуем обновление обычным коммитом.
git commit -m "Add a chemistry simulator"
git push origin main
```

Для обновления правьте файлы соответствующего тренажёра. Для снятия материала с публикации задайте `draft` или `planned`. Допустимо удалить всю папку, если её больше не нужно хранить в текущей версии. В каждом случае достаточно коммита и отправки в `main`. Карточки и пути соберутся автоматически. Черновики исключены из сайта Pages. Файлы, отправленные в публичный репозиторий, доступны через сам GitHub и историю Git.

## 5. Откатите обновление при необходимости

Если сборка не прошла, откройте журнал задачи **build** на вкладке **Actions**. Действующий сайт продолжит отдавать последнюю успешно развернутую версию. Исправьте указанную ошибку и отправьте новый коммит.

Если ошибочный коммит уже был опубликован, отмените его. В примере замените значение переменной реальным хешем из `git log`.

```powershell
# Смотрим последние коммиты и находим нужный.
git log --oneline -10

# Создаём коммит, который отменяет выбранное обновление.
$badCommit = "REPLACE_WITH_COMMIT_SHA"
git revert $badCommit

# Отправляем откат для повторной публикации через Actions.
git push origin main
```

Если нужен откат самого перехода с v1.0, сначала восстановите коммит с прежним комплектом. Затем верните источник GitHub Pages на прежнюю ветку и папку, из которых публиковалась v1.0. Проверьте действующий каталог и переход на старый адрес тренажёра.

## 6. Решите, что делать со старым адресом

Если первый пост ещё не опубликован, сразу используйте [новую прямую ссылку](https://densugatov2000-eng.github.io/chemistry-in-3d/simulator/atomic-structure/).

- **Старый адрес больше не нужен.** После проверки нового сайта можно отключить Pages в `atomic-structure-model`. Исходный репозиторий можно оставить как архив.
- **Старый адрес уже опубликован.** Сохраните старый сайт либо используйте `docs/legacy-redirect.html` из комплекта. Для перенаправления сделайте резервную копию старого `index.html`, затем поместите HTML перенаправления на его место под именем `index.html` в публикуемой папке старого репозитория. После публикации проверьте старый адрес. Этот файл не участвует в сборке основного сайта.
